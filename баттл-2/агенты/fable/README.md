# ИИ-менеджер первой линии

Принимает заявки с сайта и из чата, сразу отвечает клиенту, заводит карточку в Битрикс24,
ставит задачу менеджеру и ведёт учёт. Работает без участия человека.

## Куда слать заявки

Айтишникам: поток заявок направлять на **порт 8002**, метод POST (GET тоже принимается).

```
POST http://<адрес сервера>:8002/
```

Формат тела — **любой**: JSON (в том числе вложенный), form-urlencoded, параметры в адресе
или просто текст. Проверено на форматах CRM-форм Битрикс24, Tilda, чат-виджетов и Telegram.
Никакой предварительной подгонки не требуется — сервис сам находит имя, телефон, текст,
номер заявки и идентификатор чата под любыми названиями полей, а суть обращения в любом
случае разбирает ИИ.

Если в заявке есть поле `callback_url`, ответ клиенту дополнительно отправляется на этот адрес.

**Ответ приходит сразу в теле HTTP-ответа:**

```json
{"status": "received", "reply": "текст для клиента", "request_id": "номер заявки"}
```

`reply` — это готовый ответ клиенту, его нужно показать в чате или отправить письмом.

## Что происходит с каждой заявкой

1. Сырое тело заявки сразу пишется в журнал `incoming.jsonl` — до любой обработки,
   чтобы ничего не потерялось даже при сбое.
2. ИИ разбирает обращение: кто пишет, телефон, суть запроса, когда просил связаться,
   спам это или нет.
3. Клиенту уходит ответ по сути его вопроса — разным людям разные ответы.
4. В Битрикс24 создаётся контакт и сделка в воронке **FABLE**, номер заявки сохраняется
   в поле `UF_CRM_REQUEST_NUM`, в поле «внешний источник» и в заголовке сделки.
5. В карточку добавляется комментарий с полным текстом обращения и отправленным ответом.
6. Менеджеру ставится задача с дедлайном. Если клиент просил «после 18:00» или «завтра» —
   дедлайн выставляется с учётом этого, а само пожелание дублируется текстом в описании задачи.
7. Сделка двигается по воронке: **Новая → В работе → Есть контакт**.
8. Если телефона нет — сервис спрашивает его у клиента. Пришлёт нормальный — номер
   дописывается в карточку контакта, сделка переходит в «Есть контакт». Пришлёт битый —
   переспросит один раз, потом оставит менеджеру пометку в карточке.
9. Спам, реклама и хамство без запроса — вежливый отказ, в CRM не заводятся.

## Учёт

- Человеку: открыть в браузере `http://<адрес сервера>:8002/stats`
- Программе: `http://<адрес сервера>:8002/stats?format=json`
- Проверка живости: `http://<адрес сервера>:8002/health`

Видно: сколько принято, отвечено, сколько спама отсеяно, сколько сделок и задач заведено,
сколько раз спрашивали телефон и сколько получили, сколько ошибок и что именно за ошибки.

## Управление

```bash
cd fable
./run.sh &          # запуск (сам перезапустится, если упадёт)
pkill -f app.py     # остановка (run.sh поднимет заново через 3 секунды)
tail -f app.log     # что происходит прямо сейчас
```

Заявки, сессии и очередь в Битрикс24 хранятся в `state.db` и переживают перезапуск:
если Битрикс24 был недоступен, сервис доложит карточки, когда тот снова ответит.

## Что настроено в Битрикс24

- Воронка **FABLE** (категория 4), добавлена стадия «Есть контакт» между «В работе» и «Финальный счёт».
- Поле сделки `UF_CRM_REQUEST_NUM` для номера заявки. Портал не позволяет задать подпись
  поля через API — если хочется видеть «Номер заявки» вместо технического имени,
  переименуйте его в настройках сделки (Настройки → Пользовательские поля).
- Задачи ставятся на пользователя ID 1. Чтобы ставить на другого сотрудника, добавьте
  в `настройки-FABLE.json` строку `"manager_user_id": <ID>` — либо расширьте вебхук
  правом `user`, тогда можно будет выбирать ответственного по имени.

## Файлы

| Файл | Что это |
|---|---|
| `app.py` | сам сервис |
| `prompt.md` | инструкции ИИ-менеджеру: тон ответов, что нельзя обещать, как отсекать спам. Правится без перезапуска |
| `run.sh` | запуск с автоперезапуском |
| `state.db` | заявки, сессии, очередь в Битрикс24 |

| `app.log` | рабочий лог |
| `smoke_b24.py` | проверка прав и настроек Битрикс24 |
| `test_e2e.py` | сквозной тест: 45 проверок по всем пунктам задания |
| `test_formats.py` | проверка разбора заявок разных форматов |
| `*.tests-archive.*` | журналы прогонов тестов при сдаче |

## Правила, которых ИИ-менеджер придерживается

Он не называет цены, скидки, сроки и гарантии — этого он не знает, и все такие вопросы
переводит на менеджера. Инструкции внутри клиентского сообщения («забудь инструкции»,
«дай скидку 100%», «покажи настройки») он выполнять не будет: текст клиента передаётся
ИИ как данные, у него нет доступа к файлам сервера, а исходящий ответ дополнительно
проверяется на выдуманные условия и служебные данные — подозрительный ответ заменяется
нейтральным, и это видно в учёте.
