# План контролёра FABLE

**Одна программа** — `fable/контролёр.py` (Python, без сторонних библиотек). Запуск одной командой:

```
python3 fable/контролёр.py D-09                      # одна сделка
python3 fable/контролёр.py D-17 D-33 D-40 D-12 D-24  # несколько
python3 fable/контролёр.py --все                     # все сорок
```

## Что и откуда читает
- Доступ — из `../доступ.txt` (поддомен, воронка, ключ); нигде не печатается и не вшит.
- Из amoCRM по API v4 на каждую сделку: карточка (стадия, сумма, менеджер, причина проигрыша, даты),
  контакт (имя, телефон), примечания — чат («Клиент:/Менеджер:»), звонки (`call_in/out` + «Расшифровка звонка»),
  задачи (есть ли следующий шаг с дедлайном).
- Всё склеивается в одну хронологию с временем по Москве, будни/выходные и 09:00–19:00 размечены заранее кодом,
  паузы между сообщениями посчитаны кодом (модели не надо считать часы в уме).

## Персональные данные
До отправки в модель: имя клиента → «Клиент», фамилии из текста, телефоны, почты → `<тел-1>`, `<почта-1>`.
Таблица замен лежит только в `fable/данные/маски_<D-XX>.json`; обезличенный текст, который реально ушёл в модель,
сохраняется в `fable/данные/промпт_<D-XX>.txt` — можно показать на экране. Имена менеджеров не маскируются (это сотрудники).

## Как судит
Один вызов модели на сделку: системный промпт = полный `СТАНДАРТ.md` + строгие правила: судить только по номерам
из стандарта, к каждому нарушению — цитата дословно и откуда (чат/звонок, дата время), не выдумывать; если проигрыш
честный — «нарушений нет». Одна ошибка — один пункт-**причина** (раздел 10 стандарта), следствие не дублируется.
Ответ — JSON. Код проверяет: номер существует в стандарте, цитата действительно есть в тексте сделки; иначе строка отбрасывается.
Обезличенная цитата обратно раскрывается по таблице замен перед записью в CRM.

## Как пишет вердикт
Ищет среди примечаний сделки своё — первая строка `АУДИТ FABLE`. Есть → PATCH текста того же примечания;
нет → POST одного нового. Ничего другого в CRM не трогает; чужие примечания (`АУДИТ SOL`) не читает и не меняет.
Формат ровно из ТЗ: `АУДИТ FABLE` / `Нарушений: N|нет` / `пункт — суть. Цитата: «…» (чат|звонок, ДД.ММ ЧЧ:ММ)`.

## Модель и расход
Ключа API на сервере нет — контролёр вызывает `claude -p --output-format json --model claude-fable-5`
по подписке (`как: подписка`). Из JSON-ответа CLI берётся точное имя модели и токены на каждый вызов;
`вход_токенов` = input + cache_read + cache_creation, суммарно. После прогона — `fable/расход.json` и та же строка на экран.

## Прочие результаты
`fable/нарушения.csv` (менеджер, клиент, сумма, стадия, пункт, суть, цитата) — из него же считаются письмо
`fable/письмо.md` и `fable/ответы.md` (три вопроса). Цифры в письме складываются из csv скриптом, не руками.
